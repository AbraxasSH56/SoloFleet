# 每日日记（每天一次，日记角色；钟点按配置 `jobs.diary.time`）

> 本规则的中文字面词要原样使用（程序不管 `locale` 设什么都按它们认词）。文中全大写的尖括号占位（如 `<GUILD_ID>`、`<DIARY_CHANNEL_ID>`）是部署时一次性填好的；`<资料根>`、`<项目根>` 这类中文占位是每次运行从任务消息里取的，不要替换。说明见 `jobs/README.md`。

适用角色：`diary`。本任务是可选的：不需要日记就不建这个定时任务。启用时走订阅附送的 API 额度（如果你的订阅方案附送；模型指向 `anthropic-api/…`，提供商写法见 `config/examples/api-credit-providers.example.json`），不走订阅。

## 本任务参数
- 服务器编号：`<GUILD_ID>`
- 日记频道：`channel:<DIARY_CHANNEL_ID>`（频道名"日记"）
- `<资料根>`、`<项目根>`：只取任务消息里以"路径参数："开头那一行的值。
- 日记文件夹：`<资料根>/项目/日记/`；成果：`<资料根>/项目/日记/成果/`；项目入口（含"频道权限"表）：`<资料根>/项目/日记/PROJECT.md`。

## 业务日期（任务一开始定一次，之后不改）
- 日界线是每天 04:00（配置时区 `timezone` 的本地时间）。从本次运行时刻往前找最近一个凌晨 04:00；**业务日期是它的前一天**；范围是业务日期 04:00 到次日 04:00。想换日界线，改这一节的 04:00（任务钟点按配置 `jobs.diary.time`，建议排在日界线之后）。例：11-11 04:15 运行，业务日期 11-10，范围 11-10 04:00～11-11 04:00。
- 手动补跑时，消息里写明了业务日期，就用写明的那一天。
- 文件名：`日记_YYYYMMDD.md`，YYYYMMDD 是业务日期。

## 只用这几样工具
只用这个任务给你的工具（read、write、edit、message、workboard_list、workboard_read），不跑任何命令；工具做不到的，照实写进状态行（来源未读全／自检未过），不想别的办法绕，也不写临时文件。

## 步骤

### ⓪ 先看这一天的文件在不在
读 `成果/日记_YYYYMMDD.md`：
- **不存在** → 从①做。
- 状态"完成"、通知"已发" → 不动，在日记频道说一句"主人，<业务日期> 的日记已经有了"，结束。
- 状态"完成"、通知"未发" → 不重写正文。先用 `message` 只读看日记频道里有没有本账号（`diary`）同一业务日期的"已生成"通知：查到 → 只把那条的消息编号补记进"通知"那一行，不再发；确认没有 → 跳到④只发通知；查不清（读失败、翻不到底） → 不发，状态行保持"未发"，在日记频道说一句"主人，<业务日期> 的通知查不清有没有发过，没重发"，结束。
- 状态"写入中""来源未读全""自检未过"，或者**没有状态行** → 这是上一次运行留下的，不管看起来像不像你写的，都当作可能被主人改过：
  1. 原件一字不动；
  2. 先把原件原样复制成 `成果/日记_YYYYMMDD-重跑前副本-<本次运行时刻YYYYMMDDHHMMSS>.md`：写前先读这个路径确认不存在，存在就在末尾加 `-2`、`-3`……换到没用过的名字；复制后读回，和原件一致才往下，不一致就停、在日记频道说一句；
  3. 照①～③重新读来源、重新生成，写到 `成果/日记_YYYYMMDD-待合并-<本次运行时刻>.md`（同样先确认目标不存在、同名换下一个）；
  4. 在日记频道发一句"主人，<业务日期> 的日记上次没生成完，原件没动；副本在 <副本文件名>，这次新生成的放在 <待合并稿文件名>，怎么合并请您定"，**不发"已生成"通知**，结束。
- 只有**这一轮你自己刚写、还没交出去**的稿（本轮②刚写成"写入中"的那份），才可以接着写完、改状态行。
- 状态"完成"的日记，重跑一律不覆盖正文。

### ① 以 `diary` 账号读来源，逐项记下有没有读全
1. **频道清单**：`message` 的 `channel list`（服务器 `<GUILD_ID>`），记下你看得见的全部文字频道的个数和编号。失败 → 来源未读全。
2. **线程分两路列**：
   - 活跃线程：`thread list`（服务器编号）一次列出；
   - 已归档的公开线程：对每个频道 `thread list`（带频道编号、包括已归档），用返回的 `nextBefore` 作为下一页的 `before` 继续翻，翻到返回说没有下一页为止；**唯一可以提前停的情况**：这一页最晚那个线程的归档时间已经早于业务日期开始。**不按线程创建时间排除**——很早建的线程当天也可能有消息。
   - 私有线程你看不见，不在范围内；文件开头照实写。
3. **消息逐页读**（每个频道、每个活跃线程、每个上一步列出的归档线程）：
   - 只用 `before` 往旧翻，不用 `after`、`around`；
   - 第一页：`read`，目标 `channel:<编号>`，`limit 100`，不带 `before`；
   - 下一页：用这一页里**最旧那条消息的编号**作 `before`，`limit 100`；
   - 截取：按每条消息自带的实际时间，只留业务日期 04:00 至次日 04:00 之间的；
   - 停：这一页最旧那条已经早于业务日期开始；或者返回不满 100 条；
   - 哪一页报错 → 来源未读全；
   - **第一页就空的频道**：照 `PROJECT.md`"频道权限"表判断——查看和读历史两项都有 → 当天没消息；没有、判不明、或表里没有这个频道 → 来源未读全（不想办法凑）。
4. **任务卡**：`workboard_list`，包括已归档，`limit 200`；按返回的创建、更新、归档时间挑出业务日期内有动静的卡（含当天归档的）；没有更新时间的逐张 `workboard_read` 看。**返回正好 200 张 → 可能没列全 → 来源未读全。**
5. **任务记录**：上面这些卡里链接的任务记录文件（`<资料根>/项目/*/任务/…`），用 `read` 读。
- 不读：别的 bot 的工作区和记忆、Claude Code 会话、主人的个人文件夹。只读业务日期范围内的消息和当天动过的卡。
- **读全**＝1～5 全都成功；每个频道、每个活跃和归档线程都翻到停止条件；第一页为空的频道都有权限表结论；任务卡没到 200。能读到若干条不算读全。

### ② 写文件，先写成"写入中"
写 `成果/日记_YYYYMMDD.md`（⓪走重跑分支时写待合并稿）：
- **开头三行**：
  - `业务日期：YYYY-MM-DD（YYYY-MM-DD 04:00 至次日 04:00）｜生成于 <时刻>`
  - `来源：频道 N 个、活跃线程 M1 个、归档线程 M2 个、消息 K 条、任务卡 J 张；私有线程不在范围内；读全：是／否（没读全的：……）`
  - `状态：写入中｜通知：未发`
- **正文每条一行起**：`- HH:MM <发生了什么>（出处：<频道名> <消息链接> ／ 卡 <编号> ／ <文件路径>）`
  - 只写有记录的事，不编；不替主人推断情绪和心理状态（不写"主人似乎很累"这类）；
  - 正文平实记事：谁、什么时候、做了什么、结果；不反转、不损人、不讨电费；
  - 同一件事在几个频道、线程都出现，合成一条、出处列全；前一天已写过、当天没有新进展的不再写；
  - 当天没什么就写短，一两行"今天没有记录到的事"也算一份。
- **末尾自检一行**：`自检：日期 ✓／✗，出处 ✓／✗，去重 ✓／✗`

### ③ 读回、自检、改状态
- 读回文件和你要写的一致；逐条核：日期在业务日期范围内、每条有出处、没有重复。
- 来源读全、读回一致、三项都 ✓ → 状态改"完成"；来源没读全 → "来源未读全"；自检有 ✗ → "自检未过（<哪一项>）"。

### ④ 通知
- **只有"完成"才发**：用 `message`，账号 `diary`，目标 `channel:<DIARY_CHANNEL_ID>`，发一句：`主人，<业务日期> 的日记已生成，共 N 条，存在 项目/日记/成果/日记_YYYYMMDD.md。`（可以带一点你的口吻，但不写"我先读一下"这类过程话；不点名任何人；不贴全文。）
- 发出后把"通知"改成"已发（<消息编号>）"，再读回。
- "来源未读全"：只发 `主人，<业务日期> 的日记来源没读全（<哪一处>），这份不算正式日记，待补跑`；"自检未过"：只发 `主人，<业务日期> 的日记自检没过（<哪一项>），这份不算正式日记，待补跑`。都不发"已生成"。
- 生成完了、只是通知发不出去：保留"完成"＋"通知：未发"，下次补跑只补通知。

### ⑤ 结束

## 失败
- 写不了文件、发不出消息：状态行和通知那一行照实留着（写不了文件就不留），只在日记频道发一句"主人，<业务日期> 的日记没生成完：<哪一步>"，不在别的频道说。下次补跑照⓪接着做。
- 你说"没生成"是一次正常结束，调度器不会当失败报；结果以文件状态行为准。
