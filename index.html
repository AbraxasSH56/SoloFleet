03 — Why this way

Not the usual multi-agent setup.

A

Not a key per agent

One Claude subscription runs the crew. Frameworks often give each agent an API key.

B

Not one coding session

A standing crew in Discord, not subagents inside one coding session.

C

Your attention, guarded

Bots ask in three tiers: just do it, ask once, always wait. A ledger keeps what's open.

D

The model's, too

Code does the checking: formats, project files, missed requests, handoffs, the done gate. The model does the thinking.

Subscription use is Anthropic's call; see their help page (opens in a new tab).

More details
  • Every regular bot runs through the official claude command line (claude -p). No per-token meter per agent.
  • The usage card is on by default: model, pool, reasoning effort, files changed. The remaining-quota line needs the CodexBar command line (macOS) and two plugin options.
  • Included API credits, if your plan has them, run the scheduled audits and standby bots, and stop when they run out. No switch to paid usage.
  • What must happen is checked by a program: the done gate, read-only auditors, handoffs only through OpenClaw's tools, requests to you that weren't logged get logged, and daily model-free checks of formats, project folders and rule files. Bots still write their own records and file their own work. Programs remind once and check it happened; they don't judge.
  • The middle tier asks once, then goes with the default. The ledger spares you remembering; it can't make you look. Small jobs done in one turn get no card and no audit.
  • A task card can't be marked done until an audit passed and the result hasn't changed since. What you say is written down that turn, so sessions reset daily.
  • No patches to OpenClaw: official settings, the plugin interface, one plugin.

04 — Desktop and safety

One screen. Everyone takes turns.

  • One lock on the screen: one job at a time.
  • The rest queue in a file that survives session resets, and get called in turn.
  • A step past Claude Code, whose computer use turns a second session away.
  • Payments and submits still wait for your click.

Not a sandbox: some blocks match text, and button clicks aren't recognized yet. Safety doc (opens in a new tab)

More
  • Only the Desktop operator has screen tools; other bots hand it their screen jobs. A fixed job that calls no model moves the queue every couple of minutes and skips anyone who doesn't show up in time. The lock uses macOS file locking, so the desktop is verified on macOS only.
  • Shell commands that would drive the screen are blocked for the Desktop operator by text match, and sampled nightly. Auditors only read, apart from their own reports.
  • The six that wait for you: payment, sending to outside parties, permanent deletion, submitting a form, uploading a file, installing software. Only the owner's own Discord account clicking the card counts; one approval releases one action.
  • If a card is denied, times out or is cancelled, that thread's screen tools can only look and close windows.
  • The shell and auditor blocks match command text, so an indirect enough command could slip past; the nightly sample is there for that.
  • A mouse click on a button relies on the bot's rule to stop first, backed by the lock and the card.

06 — Before you try

Before you run it.

  • An always-on Mac; desktop verified on macOS only.
  • A Claude subscription and the claude CLI, OpenClaw, Node 24.16+, Python 3, a Discord bot per duty; optional Peekaboo for the desktop.
  • Not yet built from scratch on a fresh machine.
  • You sign in yourself; the repo never touches your login.
  • One person uses it.
