# 为什么这样搭

[English](../en/why-this-design.md) | 简体中文

这篇讲 SoloFleet 背后的取舍，并把它们和别人的做法摆在一起看。先讲整体，再讲局部。

先说在前面：**这里的单个做法，差不多都能在别处找到先例**——有人用订阅跑 agent，有人做审批收件箱，有人加评审步骤，也有人给屏幕加锁。写这篇之前我们翻过几十个项目，别人先做到的都直接点名。我们没在别处见过的，是把这些零件围着一件事配成一整套：一个人每天带一支 bot 小队，怎么做到既管得住花销，又不被消息淹没？

下面每一条都标了两种标签：

- **别处没见到**：在我们调研过的项目里没看到（如有遗漏欢迎指正）。
- **别处也做，这里多走一步**：别人也有类似做法，这里额外补了一步。

每条后面都附了仓库里的文件位置，方便你直接对照；提到其他项目时如有出入，欢迎提 issue 告诉我们。

---

## 两个问题

**账单。** 多数多智能体框架让每个 agent 拿自己的密钥去调模型 API。灵活是灵活，但花了多少只能事后在后台看到一个总数。十几个 agent 一起跑，很难说清哪句话花了多少。

**注意力。** agent 越能干，你就会用得越多，它们要你做的事也越多：批准、澄清、"你是这个意思吗"。每一问都有道理，加起来一个人接不住。把很多 agent 藏在一个输入框后面的产品，是从另一头碰到同一个问题：用户看不见里面在发生什么。

下面的每一条，都能归到这两个问题之一。

## 整体

### 1. 一份订阅养整支小队

*别处也做，这里多走一步。两个池子的分工：别处没见到。*

所有日常 bot 走同一份 Claude 订阅。OpenClaw 把每一轮交给同一台机器上登录好的官方 `claude` 命令行；`claude -p` 就是这条路的非交互写法。登录由官方命令行自己拿着，这里没有任何东西去读、去存、去转发它。

如果订阅方案附送 API 额度，就把它当作同一份订阅的第二个池子。定时的系统审计和备用 bot 用它，各走各的提供商条目和密钥，不设回退。额度用完，这些任务安静地暂停，额度回来再恢复，不会转成付费。

**别人怎么做。** 用订阅跑 agent 不新鲜。Claude Code 自带的多 agent 功能就是整队共用一份订阅，几个把 Claude Code 接进 Discord 的桥也是复用本机登录。多数通用框架则是每个 agent 自带密钥、按量付费。我们加的是：一支常驻的、有分工的小队共用一份订阅，并且两个池子各管一摊。

**日常里的样子。** 月初就知道这个月花多少。派十个 bot 干活和派一个，花的是同一个数。

**去哪看。** 第二个池子的提供商条目怎么写，在 `config/examples/api-credit-providers.example.json`；安静暂停在 `scripts/automation/api-quota-gate.mjs`。

有一点值得说一句：订阅管不管这种用法，是厂商说了算，而且这个说法以前变过。照着搭之前，先看一眼 [Anthropic 当前的帮助页面](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)。

### 2. 每条回复都看得见用了什么

*别处也做，这里多走一步。卡上的订阅余量和改动文件：别处没见到。*

每条回复底下默认带一张回复附卡：模型、这条回复走的哪个池子、推理档位、这一轮改了哪些文件。另有一行"订阅剩多少"，来自 [CodexBar](https://github.com/steipete/CodexBar) 命令行（一个 macOS 应用）：装上它，照[搭建指南](setup.md#6-外部依赖缺了会怎样)在插件配置里设两项，就有这一行；不装，卡上别的照常。

**别人怎么做。** OpenClaw 本身带用量页脚，能在每条回复后显示模型、上下文和费用。Claude Code 的状态栏把模型、档位和额度百分比放在终端底部。别的项目显示用量，多半是按 API 价算钱，放在任务结果或面板里。SoloFleet 没开官方页脚，而是让插件直接读宿主这一轮的用量状态，自己生成小卡，补上走的哪个池子、改了哪些文件，以及装了 CodexBar 之后的订阅余量。

**日常里的样子。** 不用开后台。扫一眼卡，就知道这条是谁答的、用的什么、动了哪些文件；装了 CodexBar，还看得到剩多少。

**去哪看。** `plugins/personal-inbox/execution-record.mjs`、`trailing-card.mjs` 和 `change-scan.mjs`。

### 3. 围着一个人的注意力来设计

*零件：别处也做。成套：别处没见到。*

主人的注意力被当成整个系统里最稀缺的东西，规则就是从这里出发写的。

- bot 自己能查、能做、能核对的，不问。
- 必须问的，合并成一条消息，带一个建议和两三个编号选项。按钮只有主人本人按得动，直接回数字也算。
- 请示分三档，哪类事进哪档是主人事先批好的，bot 不用逐件判断"这算不算小事"：
  - **直接做**，在日常汇报里带一句。
  - **问一次。** 到了写明的时间还没回，就照写明的默认办；主人事后说"撤"，就改回去。
  - **一定等。** 六类操作、花钱、新加人或扩大资料范围、删真实数据、改方向／规则／权限。
- 第三档的事全部登记进"等你定"台账，并有一张置顶的总表。bot 忘了登记，脚本过一会儿替它补一行。
- 提醒有节制：第一次点名一次；之后每隔几天合并提醒一回，每回有件数上限，最久没提的先提。主人说"周末再看"，就真的等到周末。
- 主人每天只收一份报告。急事不等报告，干活的 bot 直接点名主人。
- 没被叫到的 bot 不回话。在项目频道里，主人说的话由主责 bot 接住，转到对应线程，再回主区域报结果。主人不用进线程。
- 每周的系统审计会数一数这一周哪几次打扰本来可以不发生，并提出一条规则改法。

**别人怎么做。** 我们找到最接近的，是 LangChain 讲[环境式 agent](https://www.langchain.com/blog/introducing-ambient-agents)的文章和配套的收件箱：它把"找人"分成通知、提问、评审三种，排进一个地方。Gas Town 让上报逐层过滤后才到人。OpenClaw 社区里的 opencrew 按"做了能不能撤回"给动作分自主等级。好几个框架能在打了标记的工具上停下来等人批。这些都是实打实的先例。我们没找到的是中间那一档（"问一次，到期照默认办"）、带补登记的台账、有上限的提醒、每日一份报告和每周复盘合在一起。

**日常里的样子。** 一天被叫到没几次，每次都带着建议。你回一个"2"，事情就往下走。你没回，也不会丢，台账记着。照实说它的限度：这套东西让你不用记，但没法让你一定去看；只有你能定的事，你不定它就一直停着。

**去哪看。** `rules/shared-rules.zh-CN.md` 里"少打扰主人"一节；`plugins/personal-inbox/pending-ledger.mjs` 和 `request-watch.mjs`；`scripts/automation/pending-decisions.mjs`。

### 4. 杂活交给程序，模型的注意力留给要判断的事

*别处也做，这里多走一步。不调模型的每日对账：别处没见到。*

第 3 节护的是主人的注意力，这一节护的是模型的。模型每一轮的注意力是有限的：查格式、归档、记账、核对"真的做了没有"，这些靠它凭记忆去做，花掉的正是只有它能做的那件事——判断。所以每次都得做得一模一样的杂活，被隔离到程序层里去，模型的注意力只花在真正要判断的事上。

多数 agent 系统里，分工、评审、交接是写在提示词里的，指望模型照做。这在它不照做的那天之前都没问题；就算天天照做，也是在拿模型的注意力记账。

这里的做法是，把"必须发生的杂活"列出来，一件一件交给程序：

- 没有独立审计通过、或者送审后成果变了，任务卡就标不成"完成"。
- 审计角色只能读，只能写自己的报告。
- bot 只能用 OpenClaw 自己的办法派活，所以每一次交接在任务板和线程里都看得见。
- 给主人的请示没登记，就补登记。
- 每天有不调模型的脚本去查格式、拿项目文件夹和入口、总索引对账、给规则文件算指纹、把 bot 跑过的命令列出来。

需要判断的事留给模型，留在规则里。写给 bot 的规则逐步写明了靠什么保证：程序硬拦、每天检查，还是只有规则。程序只做到"提醒一句"和"查一下做了没有"，不替模型判断；让程序去判断，最后只会拦住正常干活。

**别人怎么做。** 这个立场不新。[12-factor agents](https://github.com/humanlayer/12-factor-agents) 就主张把流程走向留在自己的代码里。Claude Code 有钩子能拦住任务被标成完成，查什么由你自己写。我们做的是把"必须发生"的清单逐项过一遍，每项配上程序，并在规则里写明每一步是哪种保证。

**日常里的样子。** bot 说"做完了"不算数，卡转不转得过去由程序定。规矩不会因为哪个模型哪天状态不好就失效，模型的这一轮也不用花在归档和核对上。

**去哪看。** 所有关口都在 `plugins/personal-inbox/index.mjs` 里登记；`scripts/automation/`；`tests/` 里的测试。逐步的对应表在[开发流程](development-process.md)。

### 5. 做完不等于完成

*别处也做，这里多走一步。"送审后没改过"这项核对：别处没见到。*

凡是建了卡的活，都要过任务审计，没有"免审"一档。审计 bot 用全新的上下文，只拿到送审单和成果文件。它不读执行 bot 对经过的说明，也不重新解一遍题；它对着主人的话和验收标准，逐条核对成果。

一张任务卡要标成"完成"时，程序会依次核对五件事：有没有审计标签、有没有送审记录、有没有正式发出的"不通过"结论（只要有就拦住，就算主人同意也不能跳过）、有没有有效的"通过"结论、成果文件的指纹和送审时是否一致。

**别人怎么做。** OpenClaw 任务板的文档直接写明：完成证明是执行者自己报的，核查记录不影响完成状态。这道关口补的正是这一块。别的项目也有评审步骤；其中 ccswarm 在自己的说明里写着，它目前还不能把关口结果和被审的那一版绑在一起。Devin 的评审可以设成必过的检查，但默认只是给意见。

**日常里的样子。** 报到你面前的"完成"，是另一个 bot 对着你的原话核过的，而且核完以后没再被改动。

**去哪看。** `plugins/personal-inbox/audit-gate.mjs`、`audit-guard.mjs`；任务审计的规则在 `rules/roles/task-auditor/`。

### 6. 当轮写进记录，然后每天重置

*别处也做，这里多走一步。*

主人说出口的事，在他说的那一轮就写进记录。要接着做的事，卡也在同一轮建好。做到这一点以后，会话就直接用 OpenClaw 自带的设置每天重置，不写交接。重置后，bot 读任务记录和卡上的授权范围接着做，主人什么都不用说第二遍。

bot 干到一半撞了订阅限额，脚本会记下来，等限额恢复后叫醒同一个会话。bot 先核自己已经做了哪些，不重做、不重发。

**别人怎么做。** 把状态放在对话之外是个已有的想法。Gas Town 把工作状态记在仓库里的任务库；12-factor agents 主张每次从记录里把 agent 重建出来。多数框架靠检查点、摘要或向量记忆。这里多走的一步是：把"当轮写下来"定成硬前提，然后放心地每天清会话。

**日常里的样子。** 上下文不会越滚越长。隔天回来说一句"继续"，bot 读自己的笔记接上。

**去哪看。** `rules/shared-rules.zh-CN.md` 里"做事规矩"和"记录放哪里"两节；`templates/`；`scripts/automation/quota-resume.mjs` 和 `reset-notice.mjs`。

### 7. 仓库不带改 OpenClaw 的补丁

*别处也做，这里多走一步。*

这个仓库只用官方设置、官方插件接口和自己的一个插件，不带任何修改 OpenClaw 程序本体的补丁。OpenClaw 已经有的（只接受点名、防循环、任务板、审批卡、会话重置、`computer` 工具），原样用。

**日常里的样子。** OpenClaw 出新版时，不用每次升级都重新打一遍补丁。升完以后在自己机器上重跑测试、重新验一遍几道关口；官方文档提到，插件钩子不保证在每种运行方式下都触发。

**去哪看。** [整体架构](overview.md)里列了哪些来自 OpenClaw、哪些是这个仓库加的。

### 8. 边界写在明面上

*别处也做，这里多走一步。*

每个机制的文档都写明它拦得住什么、拦不住什么。在真机上测过的写测过，没测过的也照写。桌面安全那篇把程序认得出的四种情形和认不出的情形放在一起说。结案关口写明它拦不住"写脚本直接改任务板数据库"，这种由每天的对账事后查出来。

**日常里的样子。** 你自己搭的时候，知道哪些地方可以放心交给程序，哪些地方还得靠规则、偶尔自己看一眼。

**去哪看。** [安全设计](safety.md)；[开发流程](development-process.md)里每一步下面的"边界"。

### 9. 连"怎么改这套系统"也一起放出来

*在我们找过的范围里，别处没见到。*

这样的系统永远改不完。仓库里带着改它用的流程：一共七步，维护系统的人带着编程助手改的时候用，bot 自己接到主人的新决定时也用。配一张表，写明哪些地方必须审、哪些地方不用。还有一条我们会推荐给任何人的规矩：至少一份审计要来自另一家厂商的模型，因为同一家的模型很容易互相说服。

**去哪看。** [开发流程](development-process.md)；`builder-tools/`。

## 局部

### 桌面

只有一个 bot 操作屏幕，别的 bot 找它。

- **独占锁加排队。** 一台机器、一块屏幕、同一时间一个线程。拿不到锁的请求记进文件里的等候名单，换了会话也不丢，轮到了会被叫。Claude Code 命令行版的电脑操控也是同一时间只让一个会话用，第二个直接报错；这里多的是排队。
- **六类操作等主人。** 付款、对外发送、永久删除、提交表单、上传文件、安装软件。只有主人本人的账号点了审批卡才算批准。别的 bot 可以替主人说"不要"，不能替主人说"可以"。批一次只放行一个动作，用过就作废。OpenClaw 的 `computer` 工具本身没有逐个动作的确认；这是加在上面的，用的是官方的审批卡，只留"允许一次"和"拒绝"两个选项。
- **两道把关。** 桌面操作 bot 看到六类操作要来了，照规则自己先停。程序也认得出其中一部分，认出来就强制出卡。目前程序认得出四种情形，认不出鼠标点按钮。[安全设计](safety.md)里两边都写全了。
- **没批就是没批。** 审批卡被拒、过期或取消以后，那个线程只许看和关窗，直到新卡被批准。这一条我们没在别处见到。它是在一次真实测试之后改成硬拦的：那次 bot 把过期的卡当成网络故障，重试了。
- **命令行绕不过去。** 桌面操作 bot 的命令里出现能驱动屏幕的命令会被挡下，夜里还会抽查。

### 审计

- 任务审计和系统审计是两套，谁也不审自己，也不越过各自的范围。
- 触发深审的严重迹象是一张固定的短清单。错字、断链、偶发并已恢复的失败，改掉或记一笔，不惊动人。
- 审计只看上一轮之后变过的东西。
- 任务审计 bot 给某件活出过主意，送审时总控会考虑换一个来审。

### 决定和记录

- 一本所有 bot 都读的**决定账本**，只有总控写。旧的批准不会悄悄变成长期权限。
- 主人的新决定让已有的文字变得不对时，bot 照七步走：自己的记录当轮改，别人的告诉维护的 bot，规则自己绝不动——记进规则改法单，等主人批。
- 需要主人判断的事，转给谁都带着主人的原话。意思是在转述里丢的。
- "做完了""做不到""没找到"，往下传之前先对着真实结果核一遍；别的 bot 这么说，也一样先核。

### 文件和项目

- 一个项目，一个频道，一个文件夹。一个任务，一个线程，一份记录。用固定命令建，名字和位置一次就对。
- 每天对账，只报对不上的地方，不搬文件。bot 往哪写，有意不在写的那一刻拦；在那里拦，容易把正常干活也拦住。
- 垃圾桶是暂放的地方，不是删除。清空要主人点头。

### 额度

- bot 干到一半撞了订阅限额，脚本记下来，等限额恢复后叫醒同一个会话，叫的次数有上限。bot 先核已经做了哪些再接着做。撞了限额的定时任务只补跑一次，不补多次。
- 走附送 API 额度的那几个任务，额度没了就安静暂停，回来再恢复，到期前有提醒。用第二个池子跑定时审计，这种安排我们没在别处见到。

### Discord 上怎么摆

- 四种地方各有一个用处：工坊、带主区域和任务线程的项目频道、闲聊频道、审批频道。闲聊要变成项目，得主人开口。"频道即岗位、线程即任务"在 OpenClaw 社区里有人做过；这里多的是主区域和线程的分工、闲聊和干活分开、审批单独一个频道。
- bot 之间必须点名，没被叫到的不出声。用的是 OpenClaw 自带的只接受点名和防循环，这是社区里通行的配置。多的一步是：新的 bot 要主人同意才加入，每天的审计会查有没有没经同意的加入。
- 进度句以固定的五种开头之一起头；给主人看的东西不出现内部编号。

### 派活

- 总控按活的性质选 bot 和档位，并用一句话说明为什么。不是什么都上最强的模型，也不是什么都默认用最省的。
- 记录里写某一族"最新的"模型，不写版本号。出了新版，配置里改一处，每个 bot 跑一次小测试。

### 角色扮演

可以给 bot 配人设。人设管的是 bot 怎么说话；不管用什么口吻，结论、数字和决定都得说清楚。它是可选的，和干活的规矩分开放。见[角色](roles.md)。
