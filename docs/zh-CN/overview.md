# 整体架构

[English](../en/overview.md) | 简体中文

这篇讲整套系统：谁做什么、事情在 Discord 的哪里发生、哪些是规则哪些是程序、哪些东西会被写下来。

为什么这样选，看[为什么这样搭](why-this-design.md)。用起来什么感觉，看[日常使用](daily-use.md)。

## 一段话说完

一台机器上跑一个 [OpenClaw](https://github.com/openclaw/openclaw) 网关，里面有十几个 agent。每个 agent 有自己的 Discord bot 账号和自己的工作区，各有一份职责。主人在一个 Discord 服务器里跟它们说话。它们全部走同一份 Claude 订阅。一个插件加一批定时脚本负责检查那些必须发生的事；一套大白话写的规则管那些需要判断的事。

## 职责

整个仓库里 bot 都按职责叫。想给它们配人设，见[各职责说明](roles.md)。

| 职责 | 做什么 | 不做什么 |
|---|---|---|
| **主人** | 拍板。只出现在真要他定的地方。 | |
| **总控** | 理解需求、记录决定、派活、送审、对着主人的话核对结果、汇报。 | 不审自己。别人干活时不插话。 |
| **执行** | 在自己的线程里干具体的活，维护任务记录。 | 不自己扩大范围。不把自己的成果算作已审。 |
| **桌面操作** | 唯一能动屏幕的 bot。谁在哪个线程叫它，它就在哪个线程干。 | 没有主人本人批准，不做六类操作。 |
| **任务审计** | 对着主人的话和验收标准，审执行 bot 交上来的成果。只读。 | 不替人改、不派活、不当裁判。 |
| **系统审计** | 定时审这套系统本身：每天一次、每周一次、出了严重情况再加一次。除了自己的报告，只读。 | 不审具体的任务。 |
| **日记** | 根据记录替主人写每天的日记。 | 不接别的活。 |
| **备用** | 走附送 API 额度的后备 bot。只在主人点名要叫时才出场。 | 不接任务卡，不参与定时任务。 |

配置里用的 agent 编号见[可配置项](configuration.md)。

## 事情在 Discord 的哪里发生

| 地方 | 用来做什么 |
|---|---|
| **工坊** | 主人和总控说话的地方。下面不开线程，别的 bot 不在这里说话。 |
| **项目频道** | 一个项目一个频道。主区域接主人的话，结果也报回这里。每个项目有一个主责 bot，主人不点名说话时由它接。 |
| **任务线程** | 一个任务一个线程，开在项目频道下面。活和细节都在这里。 |
| **闲聊频道** | 聊天用。主人点名哪个 bot，它就开个线程陪聊。这里不干项目的活；聊着聊着成了正事，主人说一声，总控把它立成项目。 |
| **审批频道** | 审批卡和它的提醒出现在这里。 |

有几条规矩把这个结构撑住：

- bot 之间说话必须点名，没被点名的不回应。用的是 OpenClaw 自带的"只接受点名"设置和自带的防循环保护，没有自己另写。
- 新的 bot 要加入一件事，得主人先同意。第一版方案里列出谁执行、谁审，一次批准管到底。
- 给主人看的东西不出现内部编号，只用自然的标题。

## 一份订阅的两个池子

| 池子 | 谁在用 | 用完了会怎样 |
|---|---|---|
| **订阅** | 所有日常 bot 的对话和任务。OpenClaw 把每一轮交给同一台机器上登录好的官方 `claude` 命令行（`claude -p` 是这条路的非交互写法）。 | 这一轮带着厂商的限额提示失败。脚本记下来，限额恢复后叫醒同一个会话接着做。 |
| **附送的 API 额度**（如果你的方案有） | 定时的系统审计、每日巡查、备用 bot。各走各的提供商条目、各用各的密钥，不设回退。 | 这些任务安静地暂停，额度回来再恢复。不会转成付费，也不会倒回去扣订阅。 |

每条回复底下带一张小卡，默认就开着，写着模型、走的哪个池子、推理档位、这一轮改了哪些文件。想在小卡上看到订阅还剩多少？装上 [CodexBar](https://github.com/steipete/CodexBar) 命令行（一个 macOS 应用），再在插件配置里设两项就有，步骤见[搭建指南](setup.md#6-外部依赖缺了会怎样)。没设之前，卡上别的照常显示。

怎么接，见[搭建指南](setup.md)。

## 规则层和程序层

整套系统的底子是一句话：**程序层保基础能力，不靠模型自觉。**

事情分成两类。

- **必须发生的事。** 活审过没有？成果登记了没有？给主人的请示记了没有？是不是只有一个 bot 在动屏幕？这些交给程序，由程序去拦、每天去查、漏了去补。
- **需要判断的事。** 一个新决定影响多大？这算不算冲突？审计要不要升一级？这些留在规则里，由模型判断，系统审计事后抽查。

### 规则层

- `rules/shared-rules.zh-CN.md` 是所有 bot 共用的一套规则：先核实再开口、怎么做事、主人有新决定时怎么办、怎么说话、怎么少打扰主人、硬性约束、频道和点名、记录放哪里、撞了额度怎么办。
- `rules/roles/` 下是每份职责专有的那一小段。
- 同步脚本把两者拼成每个 bot 的 `AGENTS.md`，共用规则改一处，所有 bot 都跟着变。

写给 bot 的规则里，每一步都标了靠什么保证：程序硬拦、程序每天查，还是只有规则。

### 程序层

一个插件 `plugins/personal-inbox/`，挂在 OpenClaw 官方的插件接口上。`scripts/automation/` 下的定时脚本按命令型任务跑，不调模型。

| 保证什么 | 怎么保证 | 在哪 |
|---|---|---|
| 没有审计通过、或者送审后成果变了，任务卡转不成"完成" | 拦住这一下 | `plugins/personal-inbox/audit-gate.mjs` |
| 审计角色只读，只能写自己的报告 | 每条命令、每次写入都核 | `plugins/personal-inbox/audit-guard.mjs` |
| 屏幕同一时间只给一个线程，别的排队 | 每次屏幕调用前核锁 | `plugins/personal-inbox/desktop-lock.mjs` |
| 六类操作等主人本人批准 | 审批卡；有几种情形程序自己认得出 | `desktop-lock.mjs`、`sensitive-click.mjs` |
| bot 只用 OpenClaw 自己的办法派活 | 挡掉模型自带的派活工具 | `plugins/personal-inbox/delegation.mjs` |
| 给主人的请示，bot 忘了登记也会进台账 | 补登记一行 | `request-watch.mjs`、`scripts/automation/pending-decisions.mjs` |
| 格式守住；bot 之间点名的条数有数 | 每天检查 | `scripts/automation/daily-format-check.mjs` |
| 项目文件夹、入口、总索引对得上 | 每天对账，只报告 | `scripts/automation/project-files.mjs scan` |
| 撞额度停下的活能接上 | 限额恢复后叫醒原会话 | `scripts/automation/quota-resume.mjs` |
| bot 跑过的命令每天抽查 | 在每天的系统审计之前跑 | `scripts/automation/command-spot-check-trigger.js` |

逐步对应的完整清单在[开发流程](development-process.md)。每道关口拦得住什么、拦不住什么，在[安全设计](safety.md)。

### OpenClaw 本来就有的

这个仓库里没有任何修改 OpenClaw 程序本体的东西，用的都是现成的：多 agent 和多个 Discord 账号、只接受点名和防循环、任务板（Workboard）、子任务会话、定时任务、会话重置、插件钩子和审批卡、`computer` 屏幕工具、用量页脚、记忆。插件和脚本是在这上面加了前面说的那些。

## 哪些东西会被写下来

系统靠记录接续，不靠聊天记忆。

| 记录 | 写什么 | 谁写 |
|---|---|---|
| **任务卡**（在任务板上） | 任务本身、审计级别、授权范围（目标、允许做的、要主人确认的、停止条件） | 总控 |
| **任务记录**（一个线程一份） | 主人的原话、当前状态、等主人拍板的事、成果 | 干这件活的执行 bot |
| **项目入口**（一个项目一份） | 当前目标、状态、下一步、当前成果表 | 项目的主责 bot |
| **总索引** | 每个项目一行：频道、主责 bot、入口 | 总控 |
| **决定账本** | 主人定了的事和定了不做的事。每条有标题、日期和适用范围、原话、取代了哪条 | 只有总控写，所有 bot 读 |
| **"等你定"台账** | 每一件必须等主人的事：要定什么、建议、卡住了什么、截止时间 | 程序和 bot 的登记工具写；总控判"收到"还是"已定" |
| **规则改法单** | 哪条规则和新决定对不上了，建议改成什么，现在什么状态 | 总控。规则本身由维护系统的人在主人批准后去改 |

两个习惯让这些记录管用：

- **写穿。** 主人说出口的事，在那一轮就写进记录。要接着做的事，卡也在那一轮建好。
- **每日重置。** 会话每天用 OpenClaw 自带的重置清空。bot 再接手一件事时，读任务记录和卡上的授权范围，接着做。

这些记录的模板都在 `templates/`。

## 两套审计

- **任务审计**看 bot 交上来的东西。凡是建了卡的活都要过，没有"免审"一档。审计 bot 用全新的上下文，只拿送审单和成果文件，不读执行 bot 的解释。
- **系统审计**看系统。每天一次轻的，每周一次深的；出现清单上列的那几种严重迹象时再做一次深审，比如没经主人同意拉了 bot、主人说过的事没被记下。它只看上一轮之后变过的东西，所以开销不随历史增长。

两套审计里机械的部分，比如数数、查格式、比指纹，都由脚本做。审计 bot 读结果、做判断。

## 定时任务

| 任务 | 类型 | 做什么 |
|---|---|---|
| 每天的系统审计 | 调模型 | 轻量审计和文档维护 |
| 每日巡查 | 调模型 | 总控把一天汇成一份报告给主人 |
| 每周的系统审计 | 调模型 | 深度审计 |
| 异常深审 | 调模型 | 只有记下了严重迹象才跑 |
| 日记 | 调模型 | 日记 bot 写当天那一篇 |
| 检查、对账、提醒、额度处理、桌面排队 | 命令型，不调模型 | `scripts/automation/` 下的脚本 |

调模型的那几个任务的指令在 `jobs/`。几点跑、按哪个时区，在配置里定。

## 一件事怎么走完

1. 主人说要做什么。总控当轮记下来。
2. 事情是新的、复杂的，总控先复述，提议谁做、怎么审。主人同意一次。
3. 总控建项目（需要的话）、建任务卡（写明审计级别和授权范围）、开线程。
4. 执行 bot 在线程里干活，每干完一段留一句进度，任务记录保持最新。
5. 需要主人定的，执行 bot 带着建议和选项去问，同时登记进"等你定"台账，然后接着做不依赖这个答案的部分。
6. 做完后执行 bot 自己先核一遍成果，再请求送审。总控开一个审计线程，首帖是送审单。
7. 任务审计出报告。通过了，执行 bot 去完成那张卡；放行之前程序会核审计结果和成果指纹。
8. 执行 bot 在项目频道主区域报结果。随后程序自动补一行完成记录。
9. 晚上的巡查报告告诉主人：哪些事动了、哪些在等他、系统审计发现了什么。
