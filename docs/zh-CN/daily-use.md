# 日常使用

[English](../en/daily-use.md) | 简体中文

这篇从主人的位置看，带着小队过一天是什么样。写成从头走一遍的样子，因为这套设计只有用起来才看得明白。

## 早上：你说要做什么

打开 Discord，在**工坊**里用大白话跟总控说。在那里不用点名。

- 事情小而明确（"把标题里那个错字改了""上次那件事我们怎么定的"），总控直接做，回读一遍结果，告诉你。
- 事情是新的、复杂的，总控先把它的理解说回给你：你要什么、成果是什么、放在哪、建议谁来做、怎么审。然后问要不要开始。

你说一次"行"。这一声管到执行的 bot、审的 bot 和方案里的每一步，之后不会一步一问。

你说的话在同一轮就被写下来：写进记录；要接着做的事，同时建好任务卡。你不用说第二遍。

## 活转到项目频道里

每个项目有自己的频道，每个任务在它下面有一个线程。这些由总控建好，你同意过的 bot 由它拉进来。

从这里开始你可以不看线程。想补一句，在项目频道的**主区域**说就行：这个项目的主责 bot 不用点名就会接住，带到对应的线程，做完再回主区域告诉你结果。别的 bot 只有你点名时才回话。

bot 正干着活的时候，你在它线程里发的话会并进它当前这一轮。是对当前这件事的纠正，就并进去；是一件新的事，就当新的事办。

bot 每干完一段，会留一句简短的进度。每句开头是固定的五种之一，你和晚上的巡查都能一眼扫过去：完成、进行中、没跑成、等主人、卡住。这五个开头跟 `locale` 走：中文部署是 `完成：` `进行中：` `没跑成：` `等主人：` `卡住：`，英文部署是 `Done:` `In progress:` `Did not run:` `Waiting on owner:` `Stuck:`，每天的检查按对应的那一套去认；见[换语言](localization.md)。

## bot 需要你的时候

多数时候不需要。bot 会自己查，用常规的默认做法，事后告诉你用了哪个默认。

真要你定的时候，那条消息会写成你不记得前情也能回答的样子：

- 一两句说清这是什么事、为什么卡在这；
- 两三个带编号的选项，每个选了实际会发生什么；
- bot 自己的建议；
- 你不定会怎样。

下面有按钮，只有你按得动；直接打数字也行。你回了，bot 就接着做，不会再追问"确定吗"。

等你的这段时间，bot 接着做不依赖这个答案的部分，并把它推荐的那个选项先准备好——只做可以撤回的准备。

### 三档

你还没回的时候 bot 怎么办，看这件事在哪一档。档是你事先批好的，bot 不用自己掂量算不算小事。

| 档 | bot 怎么做 | 例子 |
|---|---|---|
| **直接做** | 做了，在日常汇报里带一句 | 归档做完的任务卡和线程；把自己用不着的临时文件挪进项目垃圾桶；按批准过的办法接上被打断的活 |
| **问一次** | 问的时候写明默认做什么、几点做。到点你没回，就照默认办；你事后说"撤"，它改回去 | 有意开得很窄。新的类别由你一类一类加 |
| **一定等** | 等你，多久都等 | 桌面的六类操作；花钱；加新的人或扩大资料范围；删真实数据；改方向、规则或权限 |

### 台账

"一定等"的事全部登记在一本**"等你定"台账**上。工坊里有一张置顶的总表，每件事写着：要定什么、建议是什么、它卡住了什么、什么时候截止，并链回原来那条请示。

- 事情第一次提出时点你的名一次。
- 之后，还开着的事每隔几天合并成一次提醒，一次几件，最久没提的在前。
- 你说"周末再看"，就到周末再提。
- "收到"和"已定"分开记。
- bot 给你发了带按钮的请示却忘了登记，脚本稍后会替它登记。

这样你不用记，事情也不容易丢。它没法让你一定去看：只有你能定的事，你不定它就一直开着。

## 要动屏幕的时候

只有**桌面操作** bot 碰屏幕。哪个 bot 需要在桌面上做点什么，就在出现这个需要的线程里点名它。

- 屏幕空着，它就开工：先说一句要做什么，做完贴结果和截图。
- 屏幕正被别处占着，它会回一句"排上了，前面还有几件"。谁都不用再来问；轮到了，程序会去叫当初提请求的那一方。
- 六类动作之前（付款、发东西给外部的人、永久删除、提交表单、上传文件、安装软件），它会停下：贴截图，说清接下来要做什么，同时**审批频道**里出现一张审批卡。

只有你本人点了这张卡，这一个动作才放行。表单可以先填好，提交那一下等你。你没来得及看，卡会过期；这不算你拒绝：这件事转进台账，到点前提醒你一次，你后来说"做吧"，就重新出一张卡。

做完以后，它把自己打开的窗口挪回原处，你原来的窗口不碰。

更多见[安全设计](safety.md)。

## 活做完的时候

执行 bot 做完，先自己核一遍成果，再请求送审。总控开一个审计线程；任务审计对着你的话和验收标准读成果文件，给出结论。

- **通过**：执行 bot 把卡完成，程序确认审计过了、之后没再改。
- **不通过**：执行 bot 拿到问题清单，返工一次。第二次还不过，交到你这里。

不管哪种，当初接你话的那个 bot 会在主区域用自己的话报结果：做了什么、结果是什么。卡还没结案，它会照实说。结案以后，程序自动补一行完成记录。

当轮就做完的小活不建卡、不送审，做完直接报。

## 晚上：一份报告

总控每天巡查一次：读当天的系统审计，扫一遍各项目的进度句，在工坊里给你一份报告：

- 每个项目动了什么、派给了谁、拉了谁进来；
- 哪些事在等你；
- 系统审计发现了什么（如果有）。

这是一天里唯一的例行消息。审计记下了严重情况的日子，另有一条深审结论单独发。你随时问一句"现在什么情况"，它当场照同样的办法扫一遍给你。

## 夜里：会话重置

会话每天清一次，定在你不用的时段。清之前和之后各有一条固定的通知。

第二天早上，你在任务线程里说"继续"就行。bot 读任务记录和卡上的授权范围，说一句上次做到哪，接着做。你在项目频道里问"昨天我交代的是什么"，它也答得对——答案是从项目入口里读出来的。

## 额度用完的时候

bot 干到一半撞了订阅限额，这一轮会失败，线程里出现一句厂商的简短报错。脚本会记下来。限额恢复后，脚本叫醒同一个会话；bot 先核自己已经做了哪些、说一句，再接着做，不重做、不重发。你要是已经自己把线程接上了，脚本就不插手。

走附送 API 额度的那几个定时审计不一样：额度没了，它们安静地暂停，不会天天报失败；额度回来再自己开始。

## 叫停

- `/stop` 停的是当前会话的当前这一轮。已经写了的文件、已经发了的消息不会撤回。
- 要立刻停下桌面操作 bot，在 Discord 的斜杠菜单里选它名下的 stop。要它自己收尾，就点名它说"停"，它会收拾好并放开屏幕。

## 闲聊频道

闲聊频道是说话的地方。在那里点名哪个 bot，它就开个线程陪你聊。它会回答问题、上网查东西；不改项目文件、不动桌面、不跑长任务。

聊着聊着成了该正经做的事，bot 会说一句"这件该立项"，然后什么都不动。你说一声、点名总控，它会把整条线程读完，复述任务，把项目建起来。

## 你不用做的事

- 在 bot 之间传话。它们自己点名对方。
- 进线程盯进度。结果会到主区域，也会进晚上的报告。
- 记着哪些事在等你。台账记着。
- 重置之后重新解释。记录里有。
- 去后台查账单。每条回复底下的卡写着模型、走的哪个池子、改了哪些文件。
- 琢磨"做完了"是不是真做完了。没审过，卡关不上。
