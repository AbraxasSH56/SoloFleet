# 开发流程

[English](../en/development-process.md) | 简体中文

这是改 SoloFleet 时用的流程。这套架构是什么、为什么这样搭，在 [README](../../README.zh-CN.md) 和[为什么这样搭](why-this-design.md)里讲；这篇只讲一件事：要改东西的时候怎么走。

两种时候都用它：

- **搭建时**：人带着编程助手改这套系统（改规则、改脚本、改插件、改配置）。
- **运行时**：系统里的 bot 接到主人的新决定，自己照着做。

底子只有一句话：**程序层保基础能力，不靠模型自觉。** "必须发生"的事（审计有没有过、成果有没有登记、请示有没有登记）交给程序去查、去拦、去补；"怎么判断"的事（影响多大、算不算冲突、要不要升级审计）留在规则里，由模型照规则判断，再由审计事后抽查。

流程一共七步：

**新决定 → 判断影响范围 → 筛冲突条目并改掉 → 施工 → 独立审计 → 读原件核对 → 记录写穿**

**什么时候走这七步**：主人定了一件新的事或改了口，会让已经写下的东西变得不对的时候。

**什么时候不走**：对象、结果、位置都明确的小事和问完就结束的问答，直接做；闲聊频道里不走，主人说要转成正事才交给总控；只读的审计角色、只写日记的角色、平时不出场的备用 bot 不走，它们听到管到别处的决定，只做"告诉总控"这一件。

**审计不是每一步都做。** 只在事先定好的、容易出漏洞的地方做，见第三节。

---

## 一、角色（按职责）

| 什么时候 | 角色 | 干什么 |
|---|---|---|
| 运行时 | 主人 | 拍板的人。只出现在真要他定的地方 |
| 运行时 | 总控 | 理解需求、记录决定、派活、送审、核对、汇报 |
| 运行时 | 执行 | 干具体的活，维护自己的任务记录 |
| 运行时 | 任务审计 | 审执行 bot 交的成果，只读 |
| 运行时 | 系统审计 | 定时审系统本身（每天、每周、出异常时），只读 |
| 运行时 | 桌面操作 | 唯一能动屏幕的 bot |
| 搭建时 | 协调位 | 只协调不动手：记决定、出指令、读原件核对 |
| 搭建时 | 施工位 | 动手改系统的编程助手会话 |
| 搭建时 | 审计位 | 独立审计，只读；**至少有一份审计来自另一家厂商的模型** |
| 搭建时 | 文档清理位 | 只读筛查：新决定把哪些旧说法架空了 |

人手少的时候，几个角色可以由同一个人或同一个助手先后担任，但有两条不能省：**造的人不审自己造的**；**至少有一份审计来自另一家厂商的模型**（同一家的模型容易互相说服）。

## 二、七步流程

每一步分三块写：做什么、靠什么保证、边界。"靠什么保证"里凡是程序，都写了它在仓库里的位置。

### 第 1 步　新决定

**做什么**
- 主人说出口的决定，在他说的那一轮就写进记录，不攒、不靠记性。
- 搭建时：协调位写进决定记录（日期、谁定、内容、理由、原话；只追加，被取代的旧条标明被哪条取代）。
- 运行时：只管一个项目的决定，由该项目的主责 bot 写进项目入口；管到多个项目或"以后都这样办"的，由总控写进决定账本（每条有标题、日期和范围、原话、取代关系；只写结论，不写过程）。**执行 bot 听到这类决定，转告总控，附原话，自己不写账本。**

**靠什么保证**
- 程序（搭建时）：收尾闸门——协调位每轮收尾时自动比对几份记录，一份动了、该跟着动的没动，就拦一次要求确认；写记录的小工具自己取时间，免得时间写错。*这两样是搭建者本机的小工具，不在仓库里。*
- 程序（运行时）：`scripts/automation/ledger-watch.mjs`——"还没入账的决定"清单，定时检查，超过一天没入账就叫醒总控来补。
- 程序（运行时）：`scripts/automation/daily-format-check.mjs`——每天查账本每条有没有日期和原话。
- 规则加抽查："主人说出口的事有没有记下"没有程序当场查，由系统审计每天查，漏了算必须深查的异常。

**边界**
- 闸门只看文件动没动，不知道该不该动，所以只拦一次、只提醒。
- 往"还没入账"清单里登记这一下，现在还要靠人记得做。

### 第 2 步　判断影响范围

**做什么**
- 先问一句：这个决定会让哪些已经写下的东西变得不对？
- 搭建时要看的：规则文件、设计和改动方案、定时任务指令、模板、记忆、各份记录、脚本里的默认值和例子。
- 运行时要看的：决定账本的旧条目、主人现况、项目入口、任务卡上的授权范围、正在跑的方案、定好的到点任务、还开着的请示、规则类文件。
- 查了哪几处、哪几处有冲突，记在这件事的任务卡或任务记录上；没有卡的，回主人的时候带一句。不写进决定账本。

**靠什么保证**
- **只有规则。** 这一步是判断，程序替不了。

**边界**
- 这是整条流程里最靠自觉的一步。第 3 步的筛查和第 7 步的回看是它的补救。

### 第 3 步　筛冲突条目并改掉

**做什么**
- 在第 2 步划出的范围里，把和新决定对不上的条目逐条找出来改掉，**不只改一处**。
- 搭建时：每新增一条主人定的决定，当轮就让文档清理位只读筛一轮；一整批做完、协调位压缩上下文之前也各筛一轮。除了核新条，还要顺带查被新决定架空的旧说法。筛出来的，协调位自己的文件当轮改；规则和程序里的并进下一份改动指令。
- 运行时：
  - bot 自己维护的记录当轮改；别人维护的，告诉维护的 bot，不替别人改。项目入口由该项目的主责 bot 改，总控也不替别的项目改。
  - 任务卡上的授权范围：照新决定收窄的可以当轮改；要扩大的，等主人重新确认。
  - **规则、范围文件、权限、定时任务这一类，bot 不自己改。** 总控把"哪份文件、哪一句、哪里对不上、建议改成什么"记进一张规则改法单（固定位置的文件，每条带状态），照"一定等主人"那一档去请示，同时登记进台账。主人批了，由维护系统的人照改法单去改；改完总控读回那份规则，对上了再把那一条标成"已改"。
  - 这类事**不建任务卡**：它不走运行时的任务审计，建了卡过不了结案关口；改法单和台账条目就是它的记录。

**靠什么保证**
- 程序（搭建时）：收尾闸门发现决定记录有新条目，提醒一次"该叫文档清理了"。
- 程序（搭建时）：`scripts/sync-shared-rules.py`——共用规则改一处，检查、写入、记指纹，推到全部角色，不漏不乱。
- 程序（运行时）：`scripts/automation/audit-blindspots.mjs`——每天给各角色目录下的规则文件算指纹，有变动的都列出来，附最近一次提交，由系统审计判断。它不管共用规则的源文件、范围文件、定时任务指令和模板。
- 程序（运行时）：请示登记兜底——`plugins/personal-inbox/request-watch.mjs` 记下 bot 发过带按钮的请示，`scripts/automation/pending-decisions.mjs` 稍后发现没登记就补一行；台账写入走 `plugins/personal-inbox/pending-ledger.mjs`（带锁）。
- 程序（运行时）：`plugins/personal-inbox/approval-reminder.mjs`——审批过期没批的事，主人和总控说话时由程序提醒一句，同一件隔几小时才再提。
- 规则加抽查：每周的系统审计查重复、互相矛盾的规则和过时文档，只出清单。

**边界**
- "哪条算冲突"是判断，程序只管提醒和事后看。
- 运行时没有专门的"文档清理"角色，靠总控自己找加每周审计兜底。
- 补登记只认带按钮的请示。
- 维护系统的人怎么定期看到规则改法单，要另外约定；不约定就只能靠主人带话。

### 第 4 步　施工

**做什么**
- 搭建时：
  - 一批新活开一个新会话；同时进行的批次有上限；指令每次给完整版，不打补丁。
  - 改之前，唯一原件留一份能恢复的副本；版本库已经记着的文本不另存，能重装、能重新生成的东西不留。
  - **硬性停止条件**，碰到就先停下问主人：装新软件；改 OpenClaw 程序本体、Discord 插件或别的第三方软件的源码；新建计划里没有的模块、任务或机制；同一条路线试三次都失败；同一个阻碍一小时毫无进展。
  - 请主人批的事攒在一起一次问，写清五样：想做什么、解决哪个问题、不做会怎样、代价、建议。
  - 测试走主人日后真实会用的路径，测试消息带标记、只在测试频道发、测完成对删。
  - 被权限拦下就停，不换办法绕。
- 运行时：复杂或改不回来的先复述等确认；建项目、建任务记录用固定命令；建卡时写明审计级别和授权范围；每干完一段留一句固定开头的进度；要主人定的事带建议和选项去问，同时登记；卡住就停下说明。

**靠什么保证**
- 程序代做：`scripts/automation/project-files.mjs`（`new-project`、`new-task`）——项目文件夹、入口、总索引一行、任务记录一次建对，名字不合规直接拒绝。建项目时顺带由 `scripts/automation/lead-free.mjs` 只给主责 bot 开这个频道的免点名。
- 程序抽查：`scripts/automation/daily-format-check.mjs`——任务记录的状态行、请示有没有写进记录、任务卡上的审计级别和授权范围、每个线程里 bot 点名 bot 的条数（多了只是线索，交审计判断是不是原地打转）。
- 程序硬拦：`plugins/personal-inbox/delegation.mjs`——bot 只能用系统自带的派活办法。
- 程序硬拦：`plugins/personal-inbox/desktop-lock.mjs` 和 `sensitive-click.mjs`——桌面操作 bot 遇到付款、对外发送、永久删除、提交表单、上传、安装这六类，停下等主人本人确认；程序在认得出的情形里自己认控件上的字，不只靠 bot 自报。`desktop-lock.mjs` 还挡住桌面操作 bot 用命令行去动屏幕。认得出哪些、认不出哪些，见[安全设计](safety.md)。
- 程序硬拦：`plugins/personal-inbox/stuck-guard.mjs`——桌面操作 bot 同一步连败两次就挡住，要求求助。
- 程序代做：`scripts/automation/quota-resume.mjs`——撞额度停在半路的活，额度恢复后由程序叫起来接着做，不重发、不重做。
- 程序代做：`scripts/automation/reset-notice.mjs`——每天会话重置前后各发一条固定通知；重置后 bot 照任务记录接着做。
- 程序硬拦（搭建时，只对"改程序本体"一条）：程序目录在编程助手的权限设置里禁止写入。*这是本机设置，不在仓库里；在你自己的助手里照样设一条。*
- 程序提醒（搭建时）：派活之后提醒挂兜底检查，不空等。*本机钩子，不在仓库里。*
- 其余靠规则。

**边界**
- 固定命令要 bot 自己调；所以每天对账查的是结果，手工做对也算对。
- bot 写文件写到哪，没有程序拦（审计角色除外），靠规则加每天对账。这是有意的取舍：写入时拦截容易误拦正常干活。

### 第 5 步　独立审计

**做什么**
- 审计的人只拿三样：目标和验收标准、主人的相关原话、要核的原件路径。不给施工方的过程说明，也不给协调位自己的判断，免得被带偏。
- 审计结论每条都要带依据（原件路径和行号、命令和输出、自己复现的步骤）；拿不出依据的只能写"推断"或"未核实"。**没依据的"必须改"，协调位自己核实了才挡下一步。**
- 审计结论要辨别，分三类：①必须改，真会出事；②写明边界就行；③文字订正。**只有①挡下一步。** 协调位可以把审计判的②升成必须改。同一个问题修了两轮只剩②③，就收口。
- 不为没人在用的东西加保护：试运行留下的旧东西、计划之外的临时产物，审计提出要保护的，按③处理或不采纳。
- 要在修、单项撤、整体退回之间选，或者后果大又没有依据：找另一家厂商的模型来回讨论，说透为止，不自己拍。

**靠什么保证**
- 程序硬拦（运行时）：`plugins/personal-inbox/audit-gate.mjs`——任务卡转成"完成"之前，依次核审计标签、有没有送审记录、报告是不是通过、成果在送审后改没改。没送审、没通过都转不了，主人批准也盖不过"不通过"。
- 程序硬拦（运行时）：`plugins/personal-inbox/audit-guard.mjs`——审计角色只许读、只许写指定位置。
- 程序事后核账（运行时）：`scripts/automation/day-watch.mjs`——有人绕过关口直接把卡写成完成，事后能查出来。
- 程序代做（运行时）：`scripts/automation/command-spot-check-trigger.js`——每天系统审计开工前，不调模型把各角色跑过的命令抽查一遍，顺带跑文件对账。
- 程序代做（运行时）：`scripts/automation/api-quota-gate.mjs`、`timed-reminders.mjs`、`quota-catchup.mjs`——系统审计任务用的额度到期就安静停下、回来自动恢复，到期前发提醒；撞了额度的审计任务恢复后补跑一次。
- 程序代做（搭建时）：审计调用脚本——每份审计指令自动带上"结论要带依据""按三类分级""不许用危险的版本库命令"三段；默认用日常审计那一档模型；只读。*仓库里有一个精简的示例，在 `builder-tools/cross-vendor-review/`。*
- 要不要审、审哪一档：**只有规则**，见第三节。

**边界**
- 关口挡不住"写脚本直接改任务板数据库"，这种靠事后核账。

### 第 6 步　读原件核对

**做什么**
- 交回来的东西，先对照主人的原话和验收标准读成果原件，再往下转。不照转"做完了"三个字。
- 说"没有""做不到"之前先查原件、先换办法；别人这么说也先追问。
- 这是审计之外的第二道，不代替审计。

**靠什么保证**
- 规则为主。
- 程序提醒（运行时）：`project-files.mjs check-project`——结案前查项目入口跟上没有；`plugins/personal-inbox/completion-notice.mjs`——没跟上的话，结案后那行完成记录末尾带一句提醒，不拦。
- 程序硬拦的一小块：`audit-gate.mjs` 的成果指纹（同第 5 步）。

**边界**
- 搭建时这一步完全靠协调位自觉。

### 第 7 步　记录写穿

**做什么**
- 运行时：状态改"完成"、成果位置写清、成果登记进项目入口、临时文件归位、发完成的进度句。
- 搭建时：几份记录每轮收尾前过一遍；留下的临时东西登记进清理清单；会话做完归档。
- 两边都一样：回头对一遍第 2 步划的范围，每一处要么已经改了，要么已经记在待办（改法单、台账）里。

**靠什么保证**
- 程序代做：`project-files.mjs add-result`——一条命令把成果登记进项目入口。
- 程序每天对账：`project-files.mjs scan`——每天在系统审计开工前不调模型跑一遍，查资料根、项目结构、入口跟没跟上、名字合不合规、bot 工作区新冒出来的东西。
- 程序代做：`completion-notice.mjs`、`small-job-notice.mjs`——结案和没建卡的小活，程序各补一行记录；`card-thread-map.mjs`——任务卡和线程自动对应。
- 程序提醒（搭建时）：收尾闸门（同第 1 步）。
- 其余靠规则。

**边界**
- 对账只报告、给建议，不自动搬文件。

## 三、哪些地方要审

### 搭建时

| 情形 | 怎么办 |
|---|---|
| 设计或改动方案，动手之前 | 交日常审计预审，判成立才开工 |
| 一批改正式系统或程序层的活，上线之前 | 两家模型各审一份（至少一家是另一家厂商），分歧拿出来来回探讨 |
| 一批上线、实测之后 | 结果审计，同上 |
| 审计判了①、返工之后 | 复核 |
| 改了程序或 bot 行为的一批 | 独立验证并进结果审计：由结果审计的审计位读代码、重跑离线测试、核施工位真实测试留下的证据（截图、读回、账本）；用真实聊天平台的测试仍由施工位做；不再另开独立验证会话 |
| 要在修、撤、退之间选；后果大又拿不准 | 找另一家模型来回讨论 |
| 定时任务、自然触发的脚本，当场造不出真实触发 | 先收口，等它自然跑过一次，协调位读原始日志核；对不上再按①处理 |
| 只改文档的收尾修订 | 不单独审，并进下一次结果审计（不跳过，只合并轮次） |
| 原因清楚、改法直接、只动本段新代码、后果小的修补 | 直接修，由下一次结果审计一并看 |
| 撤回到已经审过的版本 | 不再派审计，协调位自己核改动对比和证据 |
| 剩下的只是具体机械问题、一行级的核对 | 补完由协调位读原件核，通过就收口 |
| 同一个问题已经审了三轮、没有① | 收口，不再派复核 |
| 不碰密钥、随时能改回的小改动 | 主人批了可以先做，做完交审 |
| 纯主观的"像不像" | 不交审计，由主人判断 |
| 改动方案已经写明怎么办的、后果小的 | 照改动方案办 |
| 方向明显、后果小的细节 | 照建议直接定，写进记录，汇报带一句 |
| 正在造成损害、等不了 | 先做最小止损，再报 |

审计位选模型的几条线：一律用高档推理；淘汰掉的模型不留作兜底；兜底的顺序事先定好，每次兜底记下顶替的是谁、为什么。

### 运行时

| 情形 | 怎么办 |
|---|---|
| 建了任务卡的活 | 一律过任务审计，通过才算完成，没有免审一档；成果本身是一份文档的也一样 |
| 范围超出方案、用量超预算一半、成果要对外、临时加了别的 bot、执行者自己说拿不准 | 总控提议升级审计级别，主人确认 |
| 审计没过 | 返工只给一次；第二次还不过，交主人 |
| 任务审计 bot 明确说审不了（模型拒答） | 才换另一个模型补审；额度用完、出错不算 |
| 任务审计 bot 给这件活出过主意 | 送审时总控考虑改派别人审 |
| 问完就结束的问答、闲聊、当轮做完的小活 | 不建卡，不送审 |
| 为了对齐新决定，改自己的任务记录、改自己主责的项目入口里的状态 | 不为它单独建卡，也不单独送审；这件事本来有卡的，卡照旧走审计 |
| 系统本身 | 每天一次轻量审计，每周一次深度审计，出现严重异常另做一次 |
| 闲聊频道 | 系统审计只查两件：有没有在闲聊里干了该立项的活；没被叫到的 bot 有没有插话或自己拉别的 bot |
| bot 之间来回转手多 | 只当线索；真原地打转才记进报告，不算严重异常 |
| 六类操作、花钱、新加人或扩大资料范围、删真实数据、改方向／规则／权限 | 一定等主人本人 |

## 五、只靠规则的步骤

这些步骤程序替不了，要写进规则，并安排人或审计事后抽查：

1. 判断影响范围（第 2 步）。
2. 哪条算冲突、怎么改（第 3 步）。
3. 要不要审、审哪一档、审计结论分哪一类（第 5 步）。
4. 修、撤、退怎么选（第 5 步）。
5. 读原件之后判断对不对（第 6 步）。
6. 细节直接定还是去问主人。

写这些规则时守一条：**程序最多管"提醒一句""查一下有没有做"，不替模型判断。** 让程序去判断，只会误拦。

## 六、照自己的情况要换的地方

- 主人怎么称呼、bot 之间怎么互相称呼。
- 用什么语言说话和写文档（见第七节）。
- 订了哪家的模型、各角色用哪一档、审计位用哪家、兜底顺序。
- 额度快用完时的暂停线。
- 各定时任务几点跑、按哪个时区（上面说的"每天""每周"按自己的作息定）。
- 频道和账号的编号。
- 同时进行的批次上限、提醒间隔这类数字。

和具体部署有关的值都集中在一份配置文件里，见[可配置项](configuration.md)。

## 七、换语言时要改的地方

这套程序最早是在中文环境里做出来的，有不少地方按字面认固定的词：进度句的开头、任务记录里的小节标题、任务卡上的标签和标题、审计报告的第一行、程序发出去的固定标记，还有桌面操作 bot 认按钮的敏感词表。光译文档不够，程序认的这些词要跟着一起换。

仓库现在做到的是：语言设置 `locale`（默认 `en`，或 `zh-CN`）会切换程序认和写的那些固定词（进度句开头、任务记录里的小节标题和标签、任务卡上的标签、审计报告的第一行、程序发出去的固定标记、台账状态词、作业名）、数据根里的文件夹名和文件名、模板占位符、程序对 bot 说的指令句、回复附卡上的文字，以及审计守门拿哪个语言版本的任务指令来比对。规则、模板和任务指令有中英文两个版本，用的是和程序同一套词。想让 bot 用英文跟你说话，用回复语言那一项设置就行。桌面操作 bot 的敏感词表是安全闸门，中英文两套永远一起生效。有意没翻的东西（机器文件的键名、内部提示、发给主人的固定通知）见[换语言](localization.md)。

几个词的意思：

- **主人**：拍板的人。
- **写穿**：说出口的事当轮就写进记录。
- **改动方案**：动手前写好的改动计划。
- **审计结论的三类（①②③）**：必须改；写明边界就行；文字订正。
- **请示的三档**：直接做；问一次、到期照默认办；一定等主人。

有些能力依赖平台：屏幕操控、系统废纸篓、本机钩子、审计调用工具，都是在 macOS 和某一个编程助手上做出来的。把它们当成通用办法的一种参考实现来看。

角色扮演是可选的：给 bot 配人设只是一种玩法，不配也完全能用。
