# 管理方法的选择

以下是管理学方法向代理协作的转化。出处及阅读范围见[依据与应用](evidence-and-application.md)。选择依据是任务条件与可核查成果。

## 按问题选择

| 条件 | 方法 | 核对结果 |
| --- | --- | --- |
| 多项独立业务 | 共享必要态势，明确责任，减少传话层级；按资源安排并发 | 各任务状态可查，等待与协调成本合理 |
| 同一问题存在相互依赖的判断 | 按依赖组织直接协作，保留原始目标、来源和分歧 | 整合结果满足整体目的，交接成本有收益 |
| 新任务、环境变化或近期出错 | 提前检查低成本中间结果及脆弱入口 | 问题被及早发现并实际修正 |
| 同类任务表现稳定 | 明确成果后自主执行，过程检查采用增量或抽查 | 合格成果持续交付，干预成本降低 |
| 已知关键动作易遗漏 | 在关键节点简短核对，明确条件由工具检查 | 对应动作与结果可验证 |
| 重大变更的关键假设未验证 | 核对已有防护，按影响调查未知，重要风险转为验证动作 | 决策有依据，剩余缺口明确 |
| 积压或等待增加 | 分析任务到达、合格完成、等待阶段和资源瓶颈 | 调度变化改善等待或产出，满足成本要求 |
| 运行报告正常，目标仍未实现 | 检查真实结果、检测信号、纠正责任与回验 | 检测后有实际纠正，恢复有证据 |

## 协调与决策

Mintzberg 区分直接监督、流程约定、成果约定、专业能力和相互调整。稳定工作可用成果、技能与接口降低逐步协调成本；不确定且相互依赖的工作需要直接交流。组合依据任务依赖与已验证能力选择。

Simon 将执行与决策分工联系起来。子任务保留其所服务的整体目的；区分目标取舍与事实依据，专业选择靠近相关证据和结果责任。

OpenStax 区分重复、判定条件明确的决策与新颖、条件模糊的决策。前者采用稳定流程和工具，后者分析依据、选项与未知。条件变化时重新核验已有方法。

## 容量与反馈

借鉴 Meadows 的存量、流量和延迟：未完成任务构成积压，新任务和合格完成改变积压量。分别观察排队、执行及等待后续处理的阶段；在办任务数与实际运行并发是不同容量。

反馈连接目标、可核查结果、检测信号、纠正动作与回验。根据正常反馈延迟及已发生动作安排响应，避免把信号暂缺误判为失败。

## 原则取舍与效果

自主执行与复核分别按授权、影响及任务表现安排。共享态势采用共用记录与按需访问，控制重复加载和交接开销。

人类组织中的熟练程度、管理人数与反馈时长，需要依据代理的实际表现重新判断。方法冲突时核对假设、适用条件和证据；新增方法用相关任务比较判断质量、合格成果、干预和成本。文本推演及结构检查只说明设计或包装状态，行为改善依实际运行结果判断。
