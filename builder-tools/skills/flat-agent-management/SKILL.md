# 扁平代理协作管理

根据工作目标、依赖和已有能力设计协作，减少协调开销，让责任与成果可核查。

## 设计与调整

- 区分专业角色、独立任务实例和管理层。按工作依赖分工，保持相关执行者能直接访问所需信息；协调瓶颈先查职责、信息流和资源占用。
- 每项任务明确目标、关键约束、责任者、交付条件和来源。子任务保留所服务的整体目的；收到真实接收记录后再报告已落实，责任持续到交付或明确移交。
- 决策靠近掌握证据且承担结果责任的角色。依已有授权、决策影响和可恢复性安排自主选择、复核及升级；需要独立复核时，让复核者直接读取原始依据和成果。
- 共用权威目标与当前记录，各任务按需读取相关原文。交接携带必要约束、状态及来源；摘要用于定位证据。共享写入沿用约定的责任与并发处理方式。
- 稳定工作通过成果约定、共用技能及必要接口协调；不确定且相互依赖的判断采用直接协作。明确判定条件交给工具，语义判断由模型完成。
- 用任务到达、合格完成、积压和等待时间定位容量瓶颈。区分在办任务数与同时运行数，按资源、成本及优先级调整调度。
- 监督强度依具体任务的已验证表现调整。新任务、环境变化和复发环节提前检查；稳定环节采用增量检查或抽查。检测连接纠正责任与回验，响应考虑信号延迟和已发生动作。
- 重大调整前核对关键假设、依赖和已有防护，将有依据的重要风险转为验证或预防动作，未知项按影响调查。易遗漏的关键步骤设置简短核对。

## 推进与改进

- 失败时核查实际报错、已验证方法、任务状态与产出，在已有授权内恢复。重试有界；结果未知时先确认已发生动作，再决定后续操作。
- 按任务交付条件核验真实成果；涉及文档同步或用户审阅时，分别记录其实际状态。仍受阻时说明已核实原因、影响和所需决定。
- 整改依据实际改动、验证结果及复发情况判断。新增方法或流程对应具体缺口，用相关任务比较成果质量、人工干预及调用成本，优先改善已有机制。
