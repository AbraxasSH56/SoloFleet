# 跨厂商审计（示例）

[English](README.md)

一个通用的小示例：用**另一家厂商的命令行审计工具、只读地**审你的成果，并带几道防护。它是可选的，SoloFleet 运行时不用它。

## 为什么要有它

开发流程要求"至少一份审计来自另一家厂商"。同一家的模型容易有同样的盲区，换一家来审能抓到不一样的错。每次手动调第二个工具很容易出岔子：忘了限制它、忘了要求给依据、让它写进了仓库。这个脚本把安全的做法变成默认做法。

## 它做什么

`review.py`（Python 3，只用标准库）：

1. **开跑前核禁读清单。** 禁读清单是一个文本文件，列着审计员不许读的路径。脚本会走一遍工作目录，只要有"看着像密钥"的文件没被盖住就停（退出码 4）：按名字（`.env`、`*.pem`、`*secret*`……）、按权限（只有自己能读的文件）、按内容（私钥块、令牌样式的字符串；屏幕上只打文件名和类型，绝不打命中的内容）、或者因为太大没法扫。指向目录外面的软链接也会被标出来。
2. **自动补三段标准话**（审计指令里没有才补）：
   - 每条结论要带依据（文件和行号、命令和输出）；
   - 每条发现按三类分级：**Class 1** 必须改、**Class 2** 写明边界就行、**Class 3** 文字订正；只有 Class 1 挡下一步；
   - 不许用危险的版本库命令（`git clean`、`git reset --hard`、会丢改动的 `checkout`/`restore`、`stash`、`commit`、`push`，以及任何会写文件的命令）。
3. **运行审计工具**，有时间上限。工具最后一条回复当作报告正文。
4. **核对结果。** 前后比较工作目录（修改时间；如果是 git 仓库再比 `git status`），报告目录之外有改动就警告（退出码 6）。检查报告里有没有总判和分级标记；没有的话报告照样存下，但开头标"INCOMPLETE"（退出码 7）。
5. **报告只写进 `REPORT_DIR`。** 先解析真实路径；软链接和目录外的路径一律拒绝。已有的报告只有加 `--replace` 才覆盖，旧的先复制到 `REPORT_DIR/.replaced/`。

## 你要自己配的

| 占位 | 含义 |
|---|---|
| `<AUDIT_CLI>` | 你用的另一家厂商审计工具的命令行，用它的只读／禁写模式。**`review.py` 里的示例命令（`AUDIT_CMD`）不是真工具**，要换成你那个工具的真实参数。`<AUDIT_CLI>` 没换掉时脚本拒绝运行。 |
| `<REPORT_DIR>` | 报告唯一允许写入的目录（`REPORT_DIR`）。 |
| `<DENY_LIST_FILE>` | 你的禁读清单，一行一条路径或通配符（`DENY_LIST_FILE`），见 `deny-list.example.txt`。 |

可选：`AUDIT_WORKDIR`（要审的目录，默认当前目录）、`AUDIT_TIMEOUT_SEC`、`AUDIT_APPEND_LANG`（`en` 或 `zh`），以及 `AUDIT_CLI_CONFIG` + `AUDIT_CLI_CONFIG_SHA256`（审计工具自己的设置文件和它应有的哈希；脚本在开跑前后各核一次有没有被改）。

**重要：** 这个脚本是护栏，不是沙箱。真正的只读要靠审计工具自己的权限设置：让它禁止写入、禁止读禁读清单上的东西，并把同一份清单给这里用，脚本才能核覆盖。先拿无害的假文件试一遍。

## 用法

```bash
export AUDIT_WORKDIR=/path/to/the/repo
export REPORT_DIR=/path/to/reports            # 必须已存在
export DENY_LIST_FILE=/path/to/deny-list.txt
# 把 review.py 里的 AUDIT_CMD（或导出同名环境变量）改成你的工具的只读命令

python3 review.py --dry-run instruction.md reports/review-1.md   # 只检查，不调用工具
python3 review.py instruction.md reports/review-1.md
```

指令文件写要审什么、怎样算通过；放在被审的目录里，审计工具才读得到。

退出码：`0` 成功，`2` 用法／配置／路径错误，`4` 禁读清单或设置核对没过，`5` 审计工具失败或超时，`6` 报告已写出但运行期间工作目录有改动，`7` 报告不完整。

## 没带进来的

这个示例是从一个绑定了某个具体工具和某台机器的大脚本里提炼的，这里只留通用思路：不写任何厂商、模型或账号，你没填自己的命令之前它什么都不会调用。
