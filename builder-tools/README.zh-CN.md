# 搭建者工具（可选示例）

[English](README.md)

这个目录是**可选的**，SoloFleet 运行起来不需要里面任何东西。它给用编程助手来搭建、维护团队的人放一些示例，对应开发流程文档（`development-process.md`）。

## 里面有什么

| 路径 | 是什么 |
|---|---|
| [`cross-vendor-review/`](cross-vendor-review/README.zh-CN.md) | 一个通用的示例脚本：只读地运行另一家厂商的命令行审计工具。开跑前先核禁读清单，自动给指令补三条标准规则（结论带依据、三类分级、不许用危险的版本库命令），报告只写进指定目录。开发流程要求至少一份审计来自另一家厂商，这是安全地做到这一点的一种办法。审计命令要你自己填。 |
| [`skills/ste-document-maintenance/`](skills/ste-document-maintenance/SKILL.md) | 写作和维护过程文档、决策记录、任务交接的技能：用平实准确的措辞，并让长期任务的目标和当前状态一直看得见。引用 ASD-STE100 Issue 9 的写作原则。 |
| [`skills/flat-agent-management/`](skills/flat-agent-management/SKILL.md) | 设计、调整、审计多代理协作的技能：职责、授权、信息共享、容量和预防，以成果和成本来衡量。 |

两份技能都是中文写的，保持常见的目录结构：`SKILL.md`、`agents/*.yaml`（界面提示）、`references/*.md`。要用的话，把整个文件夹复制到你的编程助手的技能目录，再按自己项目的情况改措辞。

技能里引用的书和项目只写书名、作者和链接，不搬原文。ASD-STE100 的版权属于 ASD；技能里只有原创概括，正式标准请通过其中的链接获取。细节看 `references/` 里的出处说明。

## 没收进仓库的搭建者本机小工具

收尾闸门、写记录小工具、派活提醒钩子是搭建者本机的小工具，不在仓库里。（"程序目录禁止写入"只是编程助手本机设置里的一条规则。）团队不靠它们也能跑。
